**Minor.** Two guards change what they refuse, and one starts refusing a new
act: opening a pull request before an auditor has run, where a call log is
kept. Two rules arrive. No file leaves the product and no deny rule is added
or withdrawn.

### A pull request waits for its audit

Where `ORRERY_CALL_LOG` is set, `hooks/process-guard.sh` refuses
`gh pr create` until an `auditor` agent has run in the session since its last
pull request. `plan` and `build` now say the audit runs before every pull
request, on every route, not only inside `build`. The way past is a waiver,
`ORRERY_WAIVE="<reason>"`, which is recorded. With no call log nothing changes.

### Every refusal says who rules on it

Each guard's refusal of a command now ends with the rule that governs refusals: the person
decides, and the same outcome is not reached another way — another tool, a
script file, a respelling — unless the message names that way.

### The Bash guard stops refusing text

A destructive git verb behind a global option (`git -C <path> reset --hard`)
is no longer refused when it only appears as text — inside a `sed` edit, a
search, an issue body. It is still refused wherever anything in the command
could run it: an interpreter, a pipe into a shell, a script written and run,
an alias, a file git executes. What it does not see is written down in its
comment.

### Machine manners

The canon's surgical-changes section gains a paragraph: stop every process
you started once nothing needs it, say what you leave running, and on battery
let heavy work wait for whoever directs the work. Two rules arrive with it:
`a-subagent-leaves-nothing-running` and
`heavy-work-on-battery-waits-for-the-owner`.

The canon's attention section also says a question reaches the person in
their words: what the thing is, what it affects, what each answer does.

### Skills and agents

- `build` commits its plan to the task branch, not the default one.
- `debt` does not file a defect: a defect is fixed now. The quota is per
  feature task, and the pool is a set of area labels, queried one at a time.
- `diagnose` applies `plan`'s risk disqualifier before choosing a fix size,
  and a slowdown gets a threshold-based red command.
- `learn` files a correction only when it was meant to last.
- `doctor` says what to do about its usage, untyped-spawn and pull-request
  gate rows.
- `handoff`, `sharpen`, `architect`, `critic` and `auditor` lose statements
  their own files contradicted.

### Guard suites

The mutation pass stops at a mutant's first failing case, and the Bash
guard's suite runs its mutants side by side, one per core. The same verdicts, a
fraction of the time. `process-guard`'s status message names both of its acts.

### Install guide

`install/into-project.md` says plugin updates arrive only once auto-update is
switched on for this marketplace, and how.

**What you need to do:** nothing required. To receive future releases on
their own, enable auto-update: `/plugin` → Marketplaces → orrery → Enable
auto-update, and once per machine `gh auth setup-git` — see the install
guide, *Updates arrive only once you switch them on*. Without the second step
the background check fails quietly and the old version stays.
