**Minor.** Every tracker act goes through one script, `hooks/tracker.sh`, with
the method's classification, and nothing reaches `gh` in a project with no
tracker and no GitHub origin. `debt` follows: a debt item is a chore with an
origin. A plan lives in the work's item, and a ruled plan is built by agents
that did not write it. Behaviour you can observe changes in both directions —
some commands are refused that passed before, one that was refused passes.

### One door to the tracker

- `hooks/tracker.sh [-C <dir>] <op>` files, lists and notes items, says what
  closes one, and checks and creates labels. Two adapters ship: `none`, a register of files
  under `.orrery/work/debt/`, and `github`. A failure says why on stderr; a
  usage error names the values it accepts.
- Off GitHub nothing calls `gh`. `onboard` files its issue through the adapter
  only when the drafted config declares `github`; on a GitHub origin with no
  tracker it opens a pull request that closes nothing; with no GitHub origin it
  commits, stops, and names the branch whose pull request is yours to open.
  `review` and `handoff` use `gh pr` only on a GitHub origin. The skills say
  "the pull request, where the code host has one".
- `onboard prepare --label` is gone: the adapter files with the method's
  values only. An old invocation is refused before anything is written.
- The claims checker asks `tracker.sh labels` and tells a missing label from a
  tracker that could not answer; it also refuses `gh issue` or `gh label`
  called anywhere outside the adapter.
- The session start and `doctor` say what the tracker and the code host
  resolve to. A declared tracker Orrery does not know (`gitlab`, `""`) is
  shown as `none`, with a warning — it always ran as none; `github` with an
  origin not on GitHub is warned, since neither the pull-request gate nor the
  first-push gate fires there. The code host is read from the origin's host
  name, so a GitHub Enterprise host is recognised and a non-GitHub path that
  merely contains "github" is not.
- The rules loader enters process scope on `tracker.sh file` and `note`, the
  Bash guard reads their text as text, and the shipped allow-list takes
  `tracker.sh list` and `labels`.

### Debt is a chore with an origin

- `type/debt` is gone: a debt item is a `chore` whose body carries the heading
  `## Where it came from`, linking the work that left it. A chore without that
  heading is routine upkeep and is not counted as debt; `debt pay` prints it as
  not payable until it names its origin.
- `priority/medium` is gone: normal is the absence of a priority, and the three
  that remain are `critical`, `high` and `low`.
- `debtLabels` in `.orrery/config.json` is replaced by `areas`, the project's
  areas as bare values, and `debtPool`, the areas debt is paid from. While a
  project still declares `debtLabels` and no `areas`, it runs in legacy mode,
  and `doctor` warns. `doctor` and the session start also warn when `areas`
  holds more than eight.

### Plans live in the work's item

- A plan is written into `.orrery/work/<work>/item.md`, the work's own record,
  in the shape `skills/plan/item-format.md` gives: decisions with the
  alternative each beat, criteria, the command that checks each task — never
  the code. `planDirectory` is retired; `doctor` warns while it is declared.
- On `pair` and `consensus`, `plan` hands the ruled item to `build`, and the
  session that drafted the plan writes none of its code. `inline` is narrowed
  to one file and its tests with an obvious approach; `auditor` still runs.
- `frame` writes the agreed goal into the item, so a plan started later finds
  it. With the owner away it writes its own reading, marked not agreed, and
  the build waits for their yes.

### Guards

- The Bash guard no longer reads a `find` action that runs a reader
  (`-exec du …`) as a delete, and now refuses what it missed: `-okdir`, a
  quoted `-delete`, `rsync --delete-after`/`--remove-source-files`, `fd -x`,
  code piped into `sh` or passed to `eval`, and a delete behind `timeout`,
  `caffeinate`, `setsid` or `flock`.
- The pull-request gate's refusal for a missing record tells a project that
  ignores `.orrery/work/` to write the record — it is never committed there,
  and the file on disk is all the check needs — instead of asking it to commit
  what it cannot.
- Failures that said nothing now say why: `doctor` prints git's own message
  when the marketplace cannot be reached, the product's release workflow fails
  on anything but "release not found", and the process guard says when it
  cannot read or write its gate state.

### Smaller

- `learn` writes a standing ruling about what a project is into the project's
  own instructions, where every session and subagent reads it.
- A step written for the owner names its expected output only if that output
  was seen; otherwise it says so, and what success and failure look like.
- `sharpen` reads a message typed mid-turn, which its transcript scan missed.

### Upgrade

Move `debtLabels` to `areas` and `debtPool` in `.orrery/config.json`, then run
the plugin's `hooks/tracker.sh -C <your project> labels-create` once, so a
GitHub repository has the labels the classification files with. A project that
declared a tracker other than `github` or `none` is now told so at session
start; it ran as none before too. Remove `planDirectory` if it is
declared; existing plan files stay where they are.

`debtQuota` is no longer read: when `debtPool` is declared, a feature task
closes two debt items from it. A project that declared `debtQuota` should
remove it.

The shipped `hooks/permissions.json` gains four allow entries for
`tracker.sh list` and `tracker.sh labels`; merge them into your settings if you
want those two to run without a prompt. Restart running sessions after
updating.

### Going back

Pin the previous version. A project that has moved to `areas` keeps working on
0.34.0 only after restoring `debtLabels`, since 0.34.0 does not read `areas`.
