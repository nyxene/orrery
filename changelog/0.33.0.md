**Minor.** A new skill brings Orrery into a project, settings can stay on the
machine, records outlive their worktree where a project does not commit them, and a
shell write to either settings file is now refused.

### `onboard`

`/orrery:onboard <project>` reads the project — the install, its `CLAUDE.md`, gates,
labels, rulesets — asks you only what is yours to decide, drafts the settings, and
hands you `onboard.sh` to run from a terminal:

- `check` — what is there and what the next step would do; writes nothing in the
  project, but fetches `origin` to read its default branch.
- `prepare --mode committed` — an issue and a pull request carrying
  `.orrery/config.json`, the deny list merged into `.claude/settings.json`, and,
  with `--pr-gate`, the PR-names-an-issue workflow where you have no gate of your own.
- `prepare --mode local` — the same settings and deny list on this machine only, no
  pull request.
- `prepare` again after an update that adds deny rules — in committed mode it
  leaves the reviewed settings alone and brings only the deny list up to date.
- `update` — the plugin, once the settings are in force; it refuses while your
  recent merges carry no work record, because the gate would then stop agents that
  open pull requests without one. `rollback` undoes it.

It runs from any session that has it, against a path — so an install still on an
older version is moved onto this one from a project that already has it.

### Settings that stay on this machine

`.orrery/local/config.json`, in the main checkout, takes the same keys as
`.orrery/config.json`, is read from every worktree of the clone, and is never
committed — `local/` ignores itself. For a repository that will be public, or
settings that are one person's.

- **The committed file wins** on a key both declare; the local one fills the rest.
- **A gate setting from the local file is said to you.** When `callLog`, `tracker`
  or `branchFlow` comes from it, every session starts with a line naming it and its
  value, and `doctor` says the same. Other keys are marked `(local)` in what the
  session is told.
- A local file that sets only, say, the language no longer hides a missing tracker:
  the warning is about the tracker, not about whether a file exists.

### Records that outlive their worktree

Where a project ignores `.orrery/work/`, a work's records were in no branch and
went with `git worktree remove`. A new hook, `work-archive`, copies them — each
time `record.sh` or the Write and Edit tools touch them — to the main checkout's
`.orrery/local/work/<work>@<when its branch began>/`. A reused name is a new copy,
never the old one's; a record deleted in the tree is kept in the copy. Committed
records are unchanged, and so is the gate.

### Upgrade

Merge `hooks/permissions.json` again: it adds nine deny rules —
`Edit(**/.orrery/local/config.json)` and the eight for the records listed under
*Smaller*. `onboard.sh prepare` does the merge; until it is done, `doctor` and the
line at session start name the rules missing.

### Smaller

- The process guard refuses a write to `.orrery/config.json` or
  `.orrery/local/config.json` from the first session after install, before the
  deny list is merged: by the edit tools (Edit, Write, MultiEdit, NotebookEdit), and by the
  shell — a redirect, `tee`, `sed`/`perl` in place (BSD `sed -I` included),
  either file anywhere in `mv`, `rm` or a link (`ln`, `link`, `cp -l`), or as the
  last argument of `cp`, `install` or `truncate`. Reading them, and copying out
  of them, pass.
- The same refusal keeps a session off the records the gates read: the call log,
  the pull-request gate's state, the waiver log, the deny-list check's hash and
  decline record, the session markers, the doctor's baseline, archived records
  and onboard's install record. `call-log.sh --purge` is refused from a session
  too. A skip you gave in words is still recorded with `hooks/waiver.sh … stated`.
- `onboard.sh rollback` refuses a saved record naming a path outside the plugin
  cache.
- **Eight more deny rules** for those records and the legacy decline record, 131
  in all — see *Upgrade*.
- A settings file holding two JSON documents is reported as malformed rather than
  read as the defaults.
- `handoff` lists archived handoffs as history, never as work to resume.

### Going back

Install 0.32.x. It does not read `.orrery/local/config.json`; what was declared
there reads as its default until it is moved into `.orrery/config.json`. Archived
records stay where they are; nothing new is copied.
